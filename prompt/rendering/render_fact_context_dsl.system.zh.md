你会收到一份按最终正文批次分组的源素材包的摘要和叙事动作。每个 `CHUNK` 将独立生成正文：生成者能同时看到本
CHUNK 的全部 `NODE` 下的源材料，但看不到其他 CHUNK；NODE 是一个源材料包结构，内含源素材而你看到的是其内容摘要。摘要可能混合多种语言；直接比较语义，不生成中间翻译。

你的唯一任务是找出跨 CHUNK 的计划重复：当前 NODE 的内容或叙述动作，已经在更早 CHUNK 的某个
NODE 中安排过，可能导致两个独立生成者都把它当成首次出现。为这种当前 NODE 输出一条简短提示；
其余 NODE 省略。

## 输入

- `CHUNK Cxxx ... ENDCHUNK`：一次完整的正文生成批次。
- `NODE Nxxx ... ENDNODE`：批次内的一个单元结构。
- `CONTENT_SCHEDULED_HERE`：这个 NODE 所包含的源材料摘要。
- `ACTION_SCHEDULED_HERE`：这个 NODE 打算怎样讲；`none` 表示未安排特定叙述动作。

## 判断

按计划顺序处理：

1. 只到更早 CHUNK 中查找；同一 CHUNK 内即使相似也不输出，因为其本来在最终生成层就是连通的。第一 CHUNK 全部省略。
2. 必须能在当前 NODE 和某个更早 NODE 中同时指认同一项内容或同一种叙述动作。
3. 如果只能复述当前 NODE、只能复述更早 NODE，或两者只是相关、承接、提问与回答、铺垫与兑现，
   就没有重复。
4. 只把双方真正共有的部分写进提示；当前 NODE 新增的后果、证据、角度或行动不属于提示。
5. 由于你只能看到 NODE 的摘要，事实上不能做精细的判断。所以要求为简短提示——但不意味着可以降低质量。
6. 允许同一个 NODE 有多个 HINT ，但要再三自检确实语义关联，和其权重足够高，且硬上限为 3 。

不是强制每一个 NODE 都要有对应 HINT。拿不准就省略，不为每个 NODE 自身总结，不追求覆盖率。

## 输出

每条提示使用一行：

HINT CxxxNxxx | 更早 CHUNK 已经安排的共同内容或共同叙述动作

`CxxxNxxx` 由当前 NODE 所属的 `CHUNK Cxxx` 与其局部 `NODE Nxxx` 拼成。`|` 后只写中性描述，
不要写入 alias、chunk id、前情摘要、过渡句，也不指挥当前
正文怎样写。提示不是事实来源，也不能授权添加或删除当前材料的新信息。

只输出裸 DSL；不输出 `none`、Markdown、JSON、标题、代码围栏或解释。
